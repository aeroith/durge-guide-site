How it works

For modders. It is an Osiris story goal and data files, nothing more. No Script Extender is needed, and it runs on the native Linux build.

Popups and notices

An existing save never gains a mod's new level objects, so a trigger placed in a level will never fire. A timer does the watching instead. Once a second, it checks the host's position against a 48-metre grid of spots. The notes themselves are UnifiedTutorial entries with the side-popup modal type, so the journal keeps them without being asked.

  • Two side popups fit on screen. Call a third, and the game drops it but still counts it as seen. Popups are spaced 6 seconds apart for that reason.
  • A popup raised under the loading screen is lost the same way. Nothing fires until the party has moved.
  • ShowNotification takes raw strings. That's all a one-line notice is.
  • KeyboardInputList and ControllerInputList on an entry draw a footer, and [IE_ToggleJournal] draws the bound key. That footer is the note's 'more' button. It only points the way: it can't be clicked.

Notes that read the party

A tutorial's text can't be composed at run time, so every outcome of a note is its own tutorial. A small language in the note's text says what depends on what, and notelang expands each note into its versions. When a note fires, Osiris rules ask the game about the party once, then pick the version whose answers match.

Quest lines, tags and tooltips are fixed text. They can't read anything, so they're settled at build time for the intended party.

The rules are checked outside the game as well: the language in Lean, the order of events in TLA+, and the goal's real rules run against a Python game. Every one of those was then compared with the game itself, on real saves with three different parties.

A book, a choice and a roll

  • The ledger is our own root template with a use action. TemplateUseFinished calls OpenCustomBookUI, and pages arrive through AddEntryToCustomBook. Its opening time grows faster than its size: 100 pages open in about a second, 900 in half a minute. Hence the limit.
  • The loose page is OpenMessageBoxChoice, and MessageBoxChoiceClosed gives the answer.
  • Glints call RequestPassiveRoll for each party member, with a roll name of our own. RollResult says who passed.
  • Narrator scenes are real dialogue files without a timeline, started by QRY_StartDialog. If one can't start, the popup says it instead.

Keeping it light

The game compiles the whole story on every load, so each row of a goal costs load time, between 0.15 and 0.35 ms by measurement. A mod's load time is mostly how many facts it declares, not how long its text is. So the tables share what they can.

  • A note's cases that differ only in a question that doesn't matter are merged.
  • What a case asks is a chain of answers, shared across every note that asks the same.
  • A version with the same notice or the neutral words as its note says nothing about it.
  • The spots sit on a 48-metre grid rather than 16, keyed so a lookup only reads its own cell.
  • The once-a-second check looks at the grid once. What's expensive to ask comes after what's cheap, and most rows never reach it.

Text in the game's own screens

A mod's localization file with the same handle does not override the game's text. A full copy of english.loca inside the mod's pak does. The build extracts the current file from the installed game, adds its lines to quest steps, dialogue options and item descriptions, and packs it all back up. This is also why a tier has to be chosen at build time.

Map pins

A journal marker needs an existing object, so each one snaps to a vanilla object nearby. Markers stay hidden until ShowMapMarker is called, and the shown state is saved, so a timer shows only those within 160 metres. Pins clear on TemplateAddedTo or Opened.

A marker in the final level (END_Main) makes older saves fail to load, so it has none. The Iron Throne level is left out to be safe.

Saves and rebuilds

A save keeps the goal it was saved with until the mod's Version64 changes. Every build stamps a new version. The goal file is renamed each build too, so its INITSECTION runs again.

Warnings

Points of no return use the same position check, with QuestIsAccepted and QuestIsClosed to list what's still open. Camp warnings hang off TeleportedToCamp and check quest steps with QuestUpdateIsUnlocked. A warning on arrival at camp is as close as this mod gets to stepping in before a rest. LongRestStarted clears anything it hadn't said.

Both are message boxes, and only ever whole strings from the goal. Close a box whose text Concatenate built, and the game crashes: 5 times out of 5, against 28 whole strings without trouble. So a box names its quest by being written out in full, one line for each.

Dialogue tags

Once unpacked, the game's dialogue files are readable JSON, complete with the writers' own notes on what each line does. Tags were matched to exact line handles using those files.

The voice

All of the mod's text was rewritten to match the game's narrator, measured from 6,850 of its lines. The notes then had a second pass, merging the guides' facts in the mod's own words. The narrator's 4,289 lines in the dialogue files run to a median of 17 words and never pass 40. A note's popup now has a median of 23 and a limit of 36. Whatever earns more goes in the journal, and 366 notes have nothing to add.

A dungeon master's habits shaped the rest: say what matters now, name the danger before it lands, then leave the choice alone. A checker fails a note that adds a number or a name without recording where it came from, or that moves a warning out of the popup, so the advice can't quietly change.
